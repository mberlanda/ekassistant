## Problem statement

Employees ask questions in natural language and get grounded, cited answers
drawn from internal documents - wikis, share drives, customer support
tickets, chats - while respecting ACL boundaries.

## V1 scope

Grounded question-answering over a few high-value internal sources with
strict per-user access control and citations; abstain when answer is not
found.

## Deferred (explicitly out of scope for V1)

- Write actions
- Cross-source reasoning (requires a knowledge graph)
- Agentic multi-hop retrieval

## Pipeline architecture (as sketched by the user)

```
a. INGEST (per source, batch + CDC) - connectors
   | parse document from different formats
   | structure-aware chunk
   | embed (in trust boundary)
   | attach source ACLs as metadata
   |
b. VECTOR + KEYWORD IDX < CDC incremental + delete-propagate


c. QUERY (per request) user question + identity (group)
   | query rewrite / route
   |
d. ACL PRE-FILTER to user's group
   | hybrid search (dense + BM25)
   |
   rerank (cross-encoder)  ---> b.
   | assemble context
e. LLM: grounded, cite-or-abstain
   |
   answer + citations
```

## Key design decisions called out up front

1. Access control is enforced at retrieval time, not just at the UI.
2. Retrieval quality comes from hybrid search: dense (embeddings) plus
   keyword (BM25), combined via Reciprocal Rank Fusion (RRF).

## Working constraints

- Build incrementally. Start by dumping this context into a local file
  (this document) before writing any code.
- Ollama is installed locally. The user's internet connection is currently
  poor, so V1 must run on a small model that can be downloaded quickly for
  a proof of concept; the model choice must be easy to swap out later.
- The user wants documentation of embedding model alternatives to help
  choose the most suitable one for this project, not just a single
  unexplained pick.
- OrbStack is installed and is the Docker runtime for any containerized
  services (e.g. the vector store).

## Reference architecture spine

```
a. CLIENT / UX            - first iteration is a simple TUI
b. API GATEWAY & IDENTITY - mock authentication; backend lookup table of
                             groups; sensible defaults
c. ORCHESTRATION           - agent runtime: planner/router, tool-caller,
   (agent runtime)          state manager, approval gates
d. TOOL LAYER
e. MODEL LAYER             - LLM w/ routing, structured outputs, guardrail
                              model, embedding model
f. RETRIEVAL / MEMORY      - vector + keyword index, ACL-aware retriever,
                              short-term (session) vs long-term (user) memory
g. DATA LAYER              - governed stores, DLP / de-identification,
                              document store, audit log, feature/metadata
h. OBSERVABILITY           - tracing per run, metrics, eval harness, cost
                              attribution, prompt/version registry
i. GOVERNANCE               - data classification, ACL propagation, key
                              management, policy engine, compliance and
                              audit
```

## Environment notes

- Docker images run via OrbStack (not Docker Desktop).
- LLM inference runs locally via Ollama.
- No model has been pulled yet as of this writing; model choice is
  documented in [ADR-0004](../decisions/0004-local-llm-serving-via-ollama.md).
