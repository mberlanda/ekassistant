# Roadmap

Living status tracker for what's built vs. designed-but-not-built. Updated
as each feature group merges. For *why* something is shaped the way it is,
follow the doc links, not this page — this page only tracks *what exists*.

Workflow for any new component (nothing is currently pending, see below):
a feature branch, a PR against `main`, two independent review passes
(findings fixed between passes), then merge — no direct-to-main commits
for code once a component starts moving past its skeleton stub. Docs-only
updates (like this file) may still land directly.

| Ingest core + tiny seed corpus (`FilesystemConnector`, `chunk_document`, `run_ingest`, `ekassistant-ingest`) | [docs/design/ingest.md](design/ingest.md) | Done, tested, verified live end-to-end ([PR #3](https://github.com/mberlanda/ekassistant/pull/3)). | Ingest format adapters (HTML/PDF/DOCX parsers, `_shared.escape_accidental_heading`) | [docs/design/ingest.md](design/ingest.md), [ADR-0009](decisions/0009-ingest-format-adapters.md) | Done, tested, verified live across all 4 formats ([PR #4](https://github.com/mberlanda/ekassistant/pull/4)). `beautifulsoup4`/`pypdf`/`python-docx`, each mapped to the same `#`-heading convention the Markdown chunker already understands; PDF gets no heading synthesis (no reliable structure signal), documented as an accepted format-specific quality gap. Seed corpus grew to 7 docs/19 chunks, one new fixture per format, hand-authored per ADR-0009 (not a downloaded corpus, to avoid licensing/provenance overhead). Both review loops found real bugs: inline-tag text getting concatenated without spaces, and - more subtly - uncontrolled HTML/DOCX/PDF prose that happens to start with `"# "` (a pasted heading-style line, a ticket reference) being silently misread as a real document heading by the shared chunker, since this PR was the first time non-hand-authored content flowed through that convention. Fixed with a per-line escape helper, confirmed necessary down to the DOCX manual-line-break case |
| Retrieval (`rrf.reciprocal_rank_fusion`, `reranker.PassthroughReranker`, `retriever.retrieve`) | [docs/design/retrieval.md](design/retrieval.md), [ADR-0002](decisions/0002-acl-enforcement-at-retrieval.md), [ADR-0003](decisions/0003-hybrid-retrieval-with-rrf.md) | Done, tested, verified live end-to-end ([PR #5](https://github.com/mberlanda/ekassistant/pull/5)). ACL enforcement lives entirely inside the two index adapters (unchanged from PR #2); `retrieve()`'s only responsibility for it is to always thread the caller's real `allowed_groups` through, never skip/default it - independent review confirmed no bypass anywhere. RRF fuses dense+keyword hits (k=60 default, k=0 allowed, negative k rejected - it would otherwise silently corrupt scores rather than crash). Reranking is a documented pass-through until a cross-encoder model is pulled. Live proof: alice/carol both get the correct top-ranked VPN chunk; bob gets the exact right refund-macro section; **carol asking that same refund-macro question - support content she can't see - gets zero leakage**, only weak matches from her own docs; guest gets nothing |
| Orchestration + `POST /query` (`orchestration/pipeline.answer_question`, TUI question path) | [docs/design/orchestration.md](design/orchestration.md), [ADR-0008](decisions/0008-lightweight-orchestration.md) | Done, tested, verified live end-to-end **through the real HTTP API** ([PR #6](https://github.com/mberlanda/ekassistant/pull/6)) - this is the PR that made the whole system actually answerable. `answer_question()` = `retrieve()` then `generate_answer()`; approval gates/tool layer stay doc-level seams only, since V1 has no write action to gate. **Independent review caught a genuine, empirically-verified concurrency bug**: the keyword-index dependency was wired through FastAPI `Depends()`, which resolves each sync dependency via its own separate threadpool dispatch - not guaranteed to be the same OS thread as the route handler body, so the sqlite3 connection could be built on one thread and used on another. Reproduced directly (16/20 concurrent requests failing with `sqlite3.ProgrammingError`), fixed by constructing it inside the route handler's own function body instead, verified both by reverting-and-reconfirming-the-break and by firing real concurrent `curl` requests at a live server. Live proof through the actual API: alice's VPN/MFA question returns a grounded "Yes" with 3 correct citations; guest and carol-asking-about-inaccessible-content both abstain correctly; confirmed an infra failure (Ollama down) now correctly surfaces as an HTTP 500, never a false-positive abstain |
| Observability + eval harness (`observability/tracing.py`, `observability/eval_harness.py`, `ekassistant-eval`) | [docs/design/observability.md](design/observability.md) | Done, tested, verified live against real Qdrant + SQLite + Ollama ([PR #7](https://github.com/mberlanda/ekassistant/pull/7)). Per-run tracing (`record_run`) appends one JSON line per `/query` call (user, groups, question, retrieved chunk ids, per-stage latency, abstain reason, citation count, model names) to `data/traces.jsonl`, relying on the POSIX `O_APPEND`+`PIPE_BUF` atomic-write guarantee rather than adding a lock - verified directly with 200 concurrent writes, 0 corrupted/lost lines. Two-tier eval harness: Tier 1 is deterministic ACL/retrieval correctness across every mock user × every seed_corpus document (no LLM involved, so a failure is always a real regression); Tier 2 measures generation quality (abstain rate, and *why* - a `abstain_reason_counts` breakdown, not a flat count) over repeated runs of a fixed answerable question, deliberately a measurement rather than an assertion since `llama3.2:1b`'s unreliability at the cite-or-abstain contract is expected, documented behavior (ADR-0004), not a regression to fail the suite on. Both review loops found real gaps: a dead `citation_validation_failures` counter that could structurally never increment (replaced with the real `abstain_reason_counts` breakdown, threaded through 5 named `REASON_*` constants in `generation.py`, kept out of the LLM-facing schema so it can't confuse the model's constrained output); and real trace-log pollution from an unisolated test writing into the developer's actual `data/traces.jsonl` (fixed with an autouse fixture). Live-verified via `make eval` and a real `/query` call producing a genuine reason breakdown in both the CLI output and the trace file |
| Governance: ACL-propagation delete checks (`chunk_ids_for_source`/`all_sources` on both index adapters, `ingest/pipeline.py`'s delete-diff logic) | [docs/design/governance.md](design/governance.md), [docs/design/ingest.md](design/ingest.md) | Done, tested, verified live against real Qdrant + SQLite ([PR #8](https://github.com/mberlanda/ekassistant/pull/8)). Closed the `KNOWN GAP` documented since PR #3: `run_ingest` now diffs each source's live chunk_ids against what's already indexed (the union of what *both* indexes separately report, so pre-existing vector/keyword drift self-heals too) and deletes the difference from both - covering both a shrunk document (orphaned chunks) and a document removed from the connector entirely or a group's access revoked (previously, a revoked group could keep retrieving content indefinitely - an authorization bug, not just a staleness one). `tests/test_governance.py` runs live against real Qdrant + SQLite proving revoke-and-reingest and full-removal both reach both indexes, plus a guard against an over-broad delete affecting an unrelated document. Independent review found only two low-severity gaps (an imprecise cost-note comment, and no test exercising Qdrant's multi-page scroll pagination beyond the trivial single-page case) - both fixed, including a live test that upserts 300 chunks to force pagination across two pages. Live-verified end-to-end against the real seed corpus: manually removed a manifest entry, re-ingested (19 → 16 chunks, exactly the removed doc's count), confirmed via a real Python session against the live indexes it was gone from both and unsearchable, then restored and re-ingested back to 19 chunks. **Still-scoped-out per docs/design/governance.md**: data classification is captured at ingest but no policy acts on it yet; no separate policy engine beyond ACL group membership; local `.env` credential storage instead of a secrets manager - all explicitly deferred, not gaps this PR was meant to close |
| Ingest crawler connector (`WebCrawlerConnector`, `config/crawl_targets.yaml`, `CompositeConnector`) | [docs/design/ingest.md](design/ingest.md) (extended), [ADR-0010](decisions/0010-web-crawler-connector.md) | Done, tested, verified live against a real local HTTP server and real Qdrant + SQLite ([PR #9](https://github.com/mberlanda/ekassistant/pull/9)). The earlier deferral was about picking real target domains, not the code - resolved by making the connector genuinely domain-agnostic: zero domains are baked in, `config/crawl_targets.yaml` (empty by default) supplies seed URLs + `allowed_groups` + crawl mode at runtime, same pattern as `seed_corpus/manifest.yaml`. Two crawl modes: `single_page` (default, fetch exactly the seed URL, follow nothing) and `same_origin` (opt-in BFS crawl bounded by required `max_depth`/`max_pages`, never crossing origin boundaries). robots.txt is always checked; a single URL's fetch failure is recorded and skipped, not fatal to the run. Reuses `html_parser.py`'s existing structural extraction via a new string-based `parse_html()` entry point. **A real bug was found live, not by review**: `ingest/cli.py` originally called `run_ingest()` once per connector against the same shared indexes, and PR #8's delete-propagation treated each connector's blind spot as a mass removal - the crawler's empty-config run wiped the entire seed corpus. Fixed with a new `CompositeConnector` combining every connector into one `run_ingest()` call; documented as an explicit contract in `pipeline.py` and covered by regression tests proving both the failure mode and the fix. Independent review (fuzzing origin-boundary/redirect-escape edge cases, tracing partial-failure safety) found no further issues. Live-verified end-to-end against a real local demo site: crawled 2 pages, confirmed ACL-correct search and a real `/query` trace showing correct retrieval, then removed the crawl target and confirmed delete-propagation cleaned it up while the 7-source seed corpus stayed untouched |

V1's full scope (grounded QA, per-user ACL enforcement, citations,
abstain-when-not-found, observability, ACL-propagation governance checks,
and a domain-agnostic web crawler connector) is now done end-to-end. Every
roadmap item is complete; `config/crawl_targets.yaml` ships empty, so
crawling a real site is one config entry away whenever a concrete target
is chosen.

Each component above depended on the ones before it (retrieval needed
indexes populated by ingest, which needed the model layer for embedding;
orchestration needed retrieval; eval needed orchestration to have
something to evaluate) - that dependency order is why they're listed in
this sequence, not build priority.
