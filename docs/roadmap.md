# Roadmap

Living status tracker for what's built vs. designed-but-not-built. Updated
as each feature group merges. For *why* something is shaped the way it is,
follow the doc links, not this page — this page only tracks *what exists*.

Workflow for everything still "Not started": a feature branch, a PR against
`main`, two independent review passes (findings fixed between passes), then
merge — no direct-to-main commits for code once a component starts moving
past its skeleton stub. Docs-only updates (like this file) may still land
directly.

| Index adapters (`QdrantVectorIndex`, `SqliteKeywordIndex`) | [docs/design/retrieval.md](design/retrieval.md), [ADR-0005](decisions/0005-vector-and-keyword-store-choice.md) | Done, tested, verified live against real Qdrant + real embeddings ([PR #2](https://github.com/mberlanda/ekassistant/pull/2)). ACL enforced as a native filter inside each query (Qdrant `MatchAny` payload filter; SQLite join against a `chunk_groups` table), never post-filtered; both `search()` calls fail closed on an empty group set. Independent review specifically fuzzed for ACL-bypass, SQL-injection, and FTS5-escaping risk and found none; added multi-group partial-overlap test coverage since that was the one real gap. `SqliteKeywordIndex` has a documented single-thread constraint (sqlite3's `check_same_thread` default) that whichever PR wires this into the API Gateway needs to account for |
| Ingest core + tiny seed corpus (`FilesystemConnector`, `chunk_document`, `run_ingest`, `ekassistant-ingest`) | [docs/design/ingest.md](design/ingest.md) | Done, tested, verified live end-to-end ([PR #3](https://github.com/mberlanda/ekassistant/pull/3)). Manifest-driven local connector + structure-aware Markdown chunker (splits on headings, then paragraphs) + per-chunk dual-index writer, run against `seed_corpus/`'s 4 hand-written docs (12 chunks). `make ingest` verified live: all four mock users' access matches their groups exactly, including guest (no groups) getting zero results. **Known, deliberately-deferred gap** (documented in `pipeline.py` and covered by characterization tests, not silently assumed away): re-running ingest never diffs against a prior run, so a shrunk or removed document's stale chunks - with their original ACL - are never deleted from either index. Real blocker for any source that gets re-ingested after edits/revocation; fine for this PR's static corpus. Revisit when a source with real churn is connected (item 4/5) or before ingest runs on a schedule |
| Ingest format adapters (HTML/PDF/DOCX parsers, `_shared.escape_accidental_heading`) | [docs/design/ingest.md](design/ingest.md), [ADR-0009](decisions/0009-ingest-format-adapters.md) | Done, tested, verified live across all 4 formats ([PR #4](https://github.com/mberlanda/ekassistant/pull/4)). `beautifulsoup4`/`pypdf`/`python-docx`, each mapped to the same `#`-heading convention the Markdown chunker already understands; PDF gets no heading synthesis (no reliable structure signal), documented as an accepted format-specific quality gap. Seed corpus grew to 7 docs/19 chunks, one new fixture per format, hand-authored per ADR-0009 (not a downloaded corpus, to avoid licensing/provenance overhead). Both review loops found real bugs: inline-tag text getting concatenated without spaces, and - more subtly - uncontrolled HTML/DOCX/PDF prose that happens to start with `"# "` (a pasted heading-style line, a ticket reference) being silently misread as a real document heading by the shared chunker, since this PR was the first time non-hand-authored content flowed through that convention. Fixed with a per-line escape helper, confirmed necessary down to the DOCX manual-line-break case |
| Retrieval (`rrf.reciprocal_rank_fusion`, `reranker.PassthroughReranker`, `retriever.retrieve`) | [docs/design/retrieval.md](design/retrieval.md), [ADR-0002](decisions/0002-acl-enforcement-at-retrieval.md), [ADR-0003](decisions/0003-hybrid-retrieval-with-rrf.md) | Done, tested, verified live end-to-end ([PR #5](https://github.com/mberlanda/ekassistant/pull/5)). ACL enforcement lives entirely inside the two index adapters (unchanged from PR #2); `retrieve()`'s only responsibility for it is to always thread the caller's real `allowed_groups` through, never skip/default it - independent review confirmed no bypass anywhere. RRF fuses dense+keyword hits (k=60 default, k=0 allowed, negative k rejected - it would otherwise silently corrupt scores rather than crash). Reranking is a documented pass-through until a cross-encoder model is pulled. Live proof: alice/carol both get the correct top-ranked VPN chunk; bob gets the exact right refund-macro section; **carol asking that same refund-macro question - support content she can't see - gets zero leakage**, only weak matches from her own docs; guest gets nothing |
| Orchestration + `POST /query` (`orchestration/pipeline.answer_question`, TUI question path) | [docs/design/orchestration.md](design/orchestration.md), [ADR-0008](decisions/0008-lightweight-orchestration.md) | Done, tested, verified live end-to-end **through the real HTTP API** ([PR #6](https://github.com/mberlanda/ekassistant/pull/6)) - this is the PR that made the whole system actually answerable. `answer_question()` = `retrieve()` then `generate_answer()`; approval gates/tool layer stay doc-level seams only, since V1 has no write action to gate. **Independent review caught a genuine, empirically-verified concurrency bug**: the keyword-index dependency was wired through FastAPI `Depends()`, which resolves each sync dependency via its own separate threadpool dispatch - not guaranteed to be the same OS thread as the route handler body, so the sqlite3 connection could be built on one thread and used on another. Reproduced directly (16/20 concurrent requests failing with `sqlite3.ProgrammingError`), fixed by constructing it inside the route handler's own function body instead, verified both by reverting-and-reconfirming-the-break and by firing real concurrent `curl` requests at a live server. Live proof through the actual API: alice's VPN/MFA question returns a grounded "Yes" with 3 correct citations; guest and carol-asking-about-inaccessible-content both abstain correctly; confirmed an infra failure (Ollama down) now correctly surfaces as an HTTP 500, never a false-positive abstain |
